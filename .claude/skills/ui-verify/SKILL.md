# UI 실물 검증

사람의 QA 시간이 병목이다. **애플리케이션을 직접 읽어서 스스로 검증한다** (CB-5).
"코드상 맞으니 잘 나올 것"은 검증이 아니다.

## 실행

1. 개발 서버를 띄운다 — `mcp__Claude_Browser__preview_start`에 `.claude/launch.json`의 `dev`를 넘긴다
   (직접 실행은 `npm run dev`)
2. 바꾼 화면으로 이동한다
3. 아래 점검표를 **전부** 돌린다

## 점검표

### 1. 렌더 확인 (스크린샷보다 먼저)
`read_page`로 접근성 트리를 읽는다. 스크린샷은 눈으로 봐야 할 때만.
- 기대한 텍스트/역할(role)이 실제로 존재하는가
- 빈 상태·로딩 상태가 흉하게 남아 있지 않은가

### 2. 콘솔 에러 — **필수**
`read_console_messages`로 확인한다.
**에러가 하나라도 남아 있으면 "동작한다"고 보고하지 않는다** (GR-4).
React key 경고, hydration 경고, 404도 에러로 취급한다.

### 3. 네트워크
`read_network_requests`로 실패한 요청(4xx/5xx), 누락된 에셋을 확인한다.

### 4. 반응형
`resize_window` `preset: "mobile"` → 다시 `"desktop"`.
- 가로 스크롤이 생기지 않는가 (VIEWER 스펙 V-4)
- 텍스트가 잘리거나 겹치지 않는가
- **끝나면 반드시 `desktop`으로 되돌린다**

### 5. 접근성 (DESIGN.md GR-7)
- 인터랙티브 요소가 `read_page filter:"interactive"`에 role과 이름을 갖고 나타나는가
- 이미지에 alt가 있는가
- 키보드 Tab 순서가 시각 순서와 맞는가

### 6. 다크 모드
`resize_window` `colorScheme: "dark"`로 확인. 토큰이 아니라 하드코딩된 색은 여기서 드러난다.

### 7. 관리자 모드를 바꿨다면

- **토큰을 대신 입력하거나 만들지 마라.** 자격 증명 취급은 사용자 본인의 몫이다 (SECURITY.md §8)
  실제 GitHub 커밋이 필요한 검증은 **사용자에게 확인을 요청**한다
- 토큰 없이 확인할 수 있는 것부터 전부 확인한다: 인증 화면 렌더, 잘못된 토큰일 때의 에러 표시,
  검증 실패 시 폼 값이 남는지, 관리자 모드임이 시각적으로 드러나는지 (DESIGN.md)
- 스크린샷·DOM 덤프에 **토큰 값이 찍히지 않았는지 확인**한 뒤 보고한다
- 공개 모드에서 관리자 전용 UI가 새어나오지 않는지 본다 — 단, **숨김은 보안이 아니다** (INV-11)

## 사용자에게 보고할 때

- 스크린샷은 **바뀐 부분**만. 전체 페이지 스크린샷을 남발하지 않는다
- 발견한 문제는 고친 뒤 다시 검증하고, **고치기 전/후를 함께** 보고한다
- 점검표 중 못 돌린 항목이 있으면 그렇다고 명시한다

## 안티패턴

- 스크린샷 한 장 찍고 "잘 나옵니다" — 콘솔과 반응형을 안 본 것이다
- 콘솔 에러를 보고도 "기존에 있던 것"이라며 넘어가기 → tech-debt-tracker에 등록한다
- JS를 실행해 DOM을 고쳐놓고 통과시키기 → 검증이 아니라 조작이다. 소스를 고쳐라
