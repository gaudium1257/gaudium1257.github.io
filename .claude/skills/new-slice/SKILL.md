# 새 도메인 슬라이스 만들기

레이어 규칙 원문 → [ARCHITECTURE.md](../../../ARCHITECTURE.md) · 근거 → [ADR-0002](../../../docs/design-docs/adr/0002-layered-architecture.md)

## 먼저 판단: 어디에 놓을 것인가

`ARCHITECTURE.md §5` 의 순서로 확인한다:

1. **콘텐츠 타입·스키마인가?** → `shared/content/` (INV-9). **예외 없다.**
   앱 안에서 콘텐츠 타입을 정의하는 순간 두 앱의 진실이 갈라진다
2. 콘텐츠를 **변경**하는 코드인가? → `admin/` (INV-8)
3. 두 앱이 함께 쓰는 화면 프리미티브인가? → `shared/ui/`
4. 기존 도메인에 속하나? → 거기에 넣는다. **새 도메인을 만들지 마라**
5. 한 앱 안에서 여러 도메인이 쓰나? → `<앱>/src/shared/`
6. 위 어디에도 안 맞나? → **여기서부터 이 스킬**

도메인이 너무 잘게 쪼개지면 도메인 간 import 욕구가 생기고 INV-2 가 깨진다.

## 스캐폴드

`<앱>/src/domains/<도메인>/` 아래에 **필요한 레이어만** 만든다. 빈 레이어는 만들지 않는다.

```
domains/<도메인>/
├── types/       # 도메인 타입. 콘텐츠 스키마는 shared/content 에서 가져온다
├── config/      # 상수, 기본값
├── data/        # 저장소 접근 + 경계 파싱 (INV-3). React 금지
├── service/     # 비즈니스 규칙, 순수 함수. React·I/O 금지
├── state/       # 훅, 스토어. JSX 금지
├── ui/          # 컴포넌트. 데이터 로딩·파싱 금지
└── index.ts     # 공개 표면. 외부는 이것만 import 한다
```

**의존 방향은 아래로만**: `ui → state → service → data → config → types`

## 규칙

- `index.ts` 가 **유일한 공개 표면**이다. 외부에서 내부 파일을 직접 import 하지 않는다
- 다른 도메인을 import 하지 않는다 (INV-2). 필요하면 `shared/` 로 승격한다
- 횡단 관심사(테마·라우팅·검색)는 `<앱>/src/shared/providers/` 를 통해서만 받는다
- `data` 는 **파싱된 도메인 타입만 반환**한다. `unknown` 을 그대로 흘리지 않는다
- **도메인은 자기가 어느 탭 아래 있는지 모른다.** 라우팅은 `app/` 이 조립한다
- 파일 400줄, 함수 60줄 (INV-5)

## 스캐폴드 후 반드시

1. `npm run lint:arch` 실행 — 새 슬라이스가 규칙을 통과하는지
2. **[ARCHITECTURE.md §6 도메인 목록 표에 행 추가]** (INV-10)
3. **[docs/QUALITY_SCORE.md 에 행 추가]** — 초기 등급과 근거
4. `service` 와 `data` 에 최소 테스트 1개씩 (TESTING.md)

이 네 가지를 빼먹으면 도메인이 지도에 없는 채로 자란다.

## 안티패턴

- "일단 `ui` 부터 만들고 나중에 나누기" → 절대 안 나뉜다. 처음부터 레이어를 지킨다
- 레이어를 지키려고 `service` 에 얇은 통과 함수를 만들기 → 레이어가 비면 만들지 않는다
- 도메인 이름을 `common`, `core`, `misc` 로 짓기 → 그건 도메인이 아니라 쓰레기통이다
- viewer 의 도메인을 admin 에 복사 → 공유가 필요하면 `shared/` 로 올린다 (CB-10)
