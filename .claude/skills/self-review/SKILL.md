# 자가 리뷰

**스스로 먼저 읽지 않은 코드를 사람에게 올리지 않는다.**
사람의 주의력이 가장 희소한 자원이다. 사람에게는 판단이 필요한 것만 올린다.

## 절차

1. `git diff` (또는 `git diff --staged`)로 **변경 전체**를 읽는다. 기억이 아니라 실제 diff 를 읽는다
2. 아래 표를 순서대로 대조한다
3. 발견한 문제는 **고친 뒤** `/verify` 를 다시 돌린다
4. 고치지 않기로 한 것은 `docs/exec-plans/tech-debt-tracker.md` 에 등록한다

## 불변식 점검 (하나라도 걸리면 머지 불가)

| | 확인 |
|---|---|
| INV-1/2 | 레이어 역방향·도메인 간 직접 import 가 없는가 → `npm run lint:arch` |
| INV-3 | 외부 데이터가 스키마 파싱 없이 도메인에 들어오지 않는가. `as` 로 형태를 주장하지 않았는가 |
| INV-4 | `any`·`@ts-ignore`·`eslint-disable` 이 새로 들어오지 않았는가 |
| INV-5 | 400줄/60줄 초과 파일·함수가 없는가 |
| INV-6 | `components/ui/` 생성물을 손대지 않았는가 |
| INV-7 | 토큰·키·개인 연락처가 diff 에 없는가. `VITE_*` 에 비밀이 없는가 |
| INV-8 | **`viewer/` 에 쓰기 경로가 생기지 않았는가** |
| INV-9 | **`shared/content` 밖에서 콘텐츠 타입·스키마를 정의하지 않았는가** |
| INV-10 | 동작이 바뀌었는데 문서가 그대로인 곳이 없는가 |
| INV-11 | 이번에 내린 결정이 문서에 남았는가 (결정 로그 / ADR) |

## 두 앱 구조에서만 생기는 실수

| | 확인 |
|---|---|
| 스키마 분기 | 같은 개념이 viewer 와 admin 에 각각 정의되지 않았는가 (CB-10) |
| 한쪽만 수정 | 공유 스키마를 바꿨는데 한쪽 앱만 고치지 않았는가 |
| 복붙 | viewer 의 컴포넌트를 admin 에 복사하지 않았는가 → `shared/` 로 올려라 |

## 골든 룰 점검 (기울이는 것)

| | 확인 |
|---|---|
| GR-1 | 같은 일을 하는 헬퍼를 또 만들지 않았는가 |
| GR-2 | `a?.b?.[0]?.c ?? ''` 같은 방어적 연쇄가 있는가 → 파싱을 안 했다는 신호 |
| GR-3 | 이름이 도메인 언어인가. `handleData`, `utils2` 같은 게 없는가 |
| GR-4 | `catch {}` 가 없는가. 콘솔 에러를 남긴 채 끝내지 않았는가 |
| GR-5 | URL 로 표현해야 할 상태(검색어·필터·탭)를 로컬에 가두지 않았는가 |
| GR-6 | 한 컴포넌트가 로딩·규칙·렌더를 동시에 하지 않는가 |
| GR-7 | 시맨틱 태그·키보드 접근·alt·대비 (**양쪽 테마**) |
| GR-8 | 테스트가 구현 세부가 아니라 동작을 검증하는가 |
| GR-9 | 주석 처리된 코드·미사용 export·안 쓰는 컴포넌트가 남지 않았는가 |
| GR-10 | 한 변경이 한 가지 일만 하는가 |

## 마지막 질문

> **"다음 에이전트가 이 코드를 읽고 안전하게 고칠 수 있는가?"**

사람의 문체 취향과 달라도 괜찮다. 정확하고, 유지보수 가능하고, 읽히면 통과다.

## 보고

- 스스로 고친 것과 남긴 것을 구분해서 적는다
- **판단이 필요한 것만** 사람에게 질문으로 올린다
- 반복해서 지적받은 항목이 있으면, 문서나 린트 규칙으로 승격을 제안한다 (CB-9)
