# 문서 가드닝

에이전트는 저장소에 있는 패턴을 복제한다. 낡은 문서는 낡은 코드를 낳는다.
기술 부채는 고금리 대출이다 — **한꺼번에 갚지 말고 매일 조금씩** (CB-8).

## 실행

```bash
npm run lint:docs
```

기계가 잡는 것: 깨진 상대 링크, 색인 누락, `CLAUDE.md` 200줄 상한,
`docs/generated/` 표식, 참고자료 확인일 만료, 계획 형식.

**기계가 못 잡는 것을 사람 대신 본다** — 아래가 이 스킬의 본체다.

## 점검 항목

### 1. 코드-문서 정합
- `ARCHITECTURE.md §6` 도메인 표 ↔ 실제 `domains/` 폴더 (양쪽 앱 모두)
- `docs/QUALITY_SCORE.md` 행 ↔ 실제 존재하는 영역
- `CLAUDE.md §6` 명령어 ↔ `package.json` 의 실제 스크립트
- `docs/generated/README.md` 생성물 표 ↔ 실제 생성 스크립트
- 문서에 적힌 파일 경로가 **실제로 존재하는가**

### 2. 스펙-구현 정합
- `product-specs/` 의 동작 표 ↔ 실제 동작
  특히 **navigation-shell.md 의 검색·테마 항목**은 눈으로 확인해야 안다 (`/ui-verify`)
- 구현이 스펙과 다르면 **코드가 아니라 스펙을 먼저 고칠지** 판단한다
- `DRAFT` 스펙이 여전히 미확정인가, 아니면 코드가 이미 결정을 내렸는가
  → 코드가 결정했다면 그 사실을 스펙에 기록한다 (INV-11)

### 3. 상태값 정합
- `exec-plans/index.md` 상태 ↔ `active/`·`completed/` 실제 위치
- `active/` 에 있는데 완료 조건이 다 체크된 계획 → 완료 처리 대상
- `adr/index.md` 상태 ↔ 각 ADR 파일의 상태
- `OPEN` ADR 이 아직 열려 있는 게 맞는가

### 4. 부채 정합
- `tech-debt-tracker.md` 항목이 가리키는 파일이 아직 존재하는가
- 이미 해결됐는데 남아 있는 항목 → `해결됨` 섹션으로 이동
- 코드에 `@ts-expect-error`·임시 어댑터가 있는데 트래커에 없는 것 → 추가

### 5. 참고자료 신선도
- `docs/references/` 확인 날짜가 6개월 이상 지난 것 → 재확인 또는 삭제

### 6. 문서 비대화 (CB-2)
- `CLAUDE.md` 가 200줄에 근접했는가 → `docs/` 로 옮기고 링크만 남긴다
- 아무도 링크하지 않는 문서가 있는가 → 색인에 넣거나 지운다
- 같은 내용이 두 문서에 있는가 → 하나를 진실 원천으로 정하고 나머지는 링크로 바꾼다

## 처리 원칙

- **문서를 코드에 맞춘다.** 코드가 옳고 문서가 낡은 경우가 대부분이다
- 단, 문서가 옳고 **코드가 규범을 어긴 경우**라면 코드를 고치거나 부채로 등록한다.
  문서를 코드에 맞춰 낮추지 않는다
- 지우는 것을 두려워하지 않는다. 틀린 문서는 없는 문서보다 나쁘다
- 큰 정리는 한 번에 하지 말고 **작은 변경 여러 개**로 (GR-10)

## 마무리

1. `npm run lint:docs` 통과 확인
2. `docs/QUALITY_SCORE.md` 의 "마지막 갱신" 날짜 갱신
3. 정리 중 발견했지만 이번에 안 고친 것 → tech-debt-tracker 에 등록
4. 사용자에게 **무엇이 어긋나 있었는지** 요약 보고
   (같은 드리프트가 반복되면 규칙으로 승격 검토 — CB-9)
