# shadcn 컴포넌트 도입

규범 원문 → [docs/DESIGN.md](../../../docs/DESIGN.md)

**shadcn 은 라이브러리가 아니라 코드 생성기다.** 생성물은 우리 코드지만, 손으로 고치지 않는다 (INV-6).

## 새 컴포넌트가 필요할 때

1. **이미 있는지 먼저 확인** — `shared/ui/` 를 훑는다. 비슷한 게 있으면 그걸 쓴다 (GR-1)
2. **`npm run ui:add <component>`** 로 추가한다.
   이 명령은 CLI 실행 + **import 경로 교정**을 함께 한다 —
   `npx shadcn add` 를 직접 부르지 마라 (아래 참고)
3. `shared/ui` 의 배럴(`index.ts`)에 export 를 추가한다
4. 앱에서는 `shared/ui` 를 통해서만 import 한다. `components/ui/` 를 직접 가리키지 않는다

### 왜 `npm run ui:add` 인가

shadcn CLI 가 `utils` 별칭을 잘못 해석해 **무관한 npm 패키지를 import 하는 코드**를
생성하는 경우가 있다. 그대로 두면 서드파티 코드가 모든 UI 컴포넌트에 들어온다
([SECURITY.md](../../../docs/SECURITY.md) 의존성 항목).

손으로 고치면 INV-6 을 깨므로 **교정을 스크립트로 기계화**했다 (CB-9).
`lint:arch` 가 교정되지 않은 import 를 잡는다.

## 커스터마이즈가 필요할 때 — 이 순서로

| 원하는 것 | 방법 |
|---|---|
| 색·간격·라운드·폰트 | **테마 토큰**을 고친다. 컴포넌트를 건드리지 않는다 |
| variant 추가 | 생성물을 고치지 말고 `shared/ui` 에 **래퍼**를 만든다 |
| 동작 변경·조합 | `shared/ui` 에 래퍼 컴포넌트 (예: `ConfirmDialog` 가 `Dialog` 를 감쌈) |
| 그래도 불가능 | ADR 을 쓰고 생성물을 fork 한다. **마지막 수단** |

훅이 `**/components/ui/**` 편집을 차단한다. 차단당했다면 위 표를 다시 보라 — 대부분 래퍼가 답이다.

## 스타일 규칙 (DESIGN.md)

- **하드코딩된 hex 색, 매직 `px` 금지.** 토큰으로 표현한다
  → 테마 토글이 토큰만 바꾸므로, 하드코딩된 색은 다크 모드에서 그대로 남아 깨진다
- 다크 모드는 토큰 레벨에서 해결한다. 컴포넌트에 `isDark` 분기를 넣지 않는다
- `className` 조합은 `cn()` 유틸을 쓴다 (직접 문자열 결합 금지)

## 추가 후

1. 실제로 쓰는 화면에서 렌더된다 — `/ui-verify` 로 확인 (**양쪽 테마 모두**)
2. 접근성: 키보드 조작과 포커스 링이 살아 있는지 확인 (GR-7)
3. **쓰지 않게 된 컴포넌트는 지운다** (GR-9). 필요해지면 다시 가져오면 된다 —
   생성기가 끌어온 의존성이 남아 있는지도 함께 확인한다
