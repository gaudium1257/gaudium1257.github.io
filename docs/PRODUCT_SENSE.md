# PRODUCT_SENSE.md — 제품 판단 기준

무엇을 만들지 애매할 때 이 문서를 기준으로 판단한다. 매번 물어볼 필요는 없다.

## 이 제품이 이기는 조건

**심사자가 30초 안에 "이 사람은 무엇을 할 수 있는가"를 파악하는 것.**
그 외의 모든 기능은 이 목표에 종속된다. admin 조차 이 목표의 하위 수단이다 —
편집이 쉬워야 콘텐츠가 최신으로 유지되기 때문이다.

## 우선순위

1. **콘텐츠가 정확하고 최신인가** — 낡은 포트폴리오는 없는 것보다 나쁘다
2. **읽기 쉬운가** — 위계, 스캔 가능성, 모바일
3. **본인이 계속 업데이트할 수 있는가** — admin 이 불편하면 콘텐츠가 낡는다
4. 그 다음이 시각적 완성도

## 기본 판단 (묻지 말고 이렇게)

| 상황 | 기본 판단 |
|---|---|
| 기능을 넣을까 말까 | **넣지 않는다.** 심사자가 쓰지 않을 기능이면 부채다 |
| 배너에 항목을 추가할까 | **아니다.** 탭 5개·도구 3개가 상한이다 (스펙) |
| viewer 에 인터랙션을 넣을까 | 정보 이해를 돕는 것만. 장식용 애니메이션은 보류 |
| admin 을 예쁘게 만들까 | 아니다. 빠르고 정확하게 편집되면 된다 |
| 데이터 모델을 유연하게 할까 | 지금 필요한 만큼만. **추측 기반 확장성 금지** |
| 라이브러리를 추가할까 | 먼저 없이 해본다. 필요가 증명되면 ADR 을 쓴다 (CB-7) |
| 다국어를 넣을까 | **아니다.** 만들지 않기로 결정했다 (ADR-0004) |
| Home 에 전부 보여줄까 | 아니다. Home 은 **요약**이다. 전체는 각 섹션에 있다 |

## 사용자에게 물어야 하는 것

다음은 기본 판단으로 결정하지 않는다:
- 어떤 이력·프로젝트·논문을 공개할 것인가 (본인의 판단 영역)
- 연락처를 어디까지 노출할 것인가 ([SECURITY.md](SECURITY.md))
