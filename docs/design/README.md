# 디자인 시안 — "깔끔한 기술 스택 (Clean Stack)"

구현의 기준이 되는 디자인입니다. 시안 캔버스: <https://claude.ai/artifact/95ysTmLFNbQUmphosPmcRx> (홈 · 프로젝트 상세 · 상세(데이터가 적은 프로젝트) · 전체 목록 × 한국어/English × 1440/390, 14개 아트보드, 모두 인터랙티브).
시안은 [`mockup/sys/gen.py`](mockup/sys/gen.py) 하나에서 생성됩니다. 같은 마크업이 ① Tailwind로 컴파일한 정적 페이지 8개(`mockup/proto/sys-*`)와 ② 캔버스 아트보드가 됩니다. 디자인을 바꿀 때는 생성기를 고치고, 다시 렌더링·검증한 뒤 캔버스에 올립니다(맨 아래 "시안 다시 만들기").

시안의 클래스 문자열이 그대로 실제 컴포넌트의 클래스가 됩니다. 시안과 사이트가 같은 Tailwind 토큰과 유틸리티를 씁니다.

> 이전 방향 "움직이는 포스터(Moving Poster)"는 주인의 요청(2026.10)으로 바뀌었습니다: 기하학 요소가 과함 → 덜어내기, 방향은 **깔끔함 · 신뢰감 · 기술 스택의 시각화**, 레이아웃은 **미니멀 텍스트 중심 · GitHub 링크 연동 · 컴포넌트 중심**, 프로젝트 성격에 따라 달라지되 **기본 양식 하나**로. 이전 생성기는 git 기록(`5e95bac`, `de0d379`)에 남아 있습니다.

## 콘셉트

흰 바탕 위의 잘 정리된 기술 문서. 첫 화면이 "이 사람이 무엇으로 무엇을 만드는가"에 답합니다.

1. **글이 페이지를 끌고 간다.** 크기와 굵기로 위계를 만들고, 장식 도형은 없습니다. 움직임도 없습니다(색 전환만).
2. **모든 주장은 근거를 가리킨다.** 기술은 그 기술을 쓴 프로젝트로, 프로젝트는 GitHub 저장소로, 수상과 프로젝트는 서로를 가리킵니다. GitHub 숫자는 언제 받아 온 값인지 함께 씁니다.
3. **테두리·패널 = 코드에서 나온 데이터.** 기술 스택 지도, 저장소 카드, 상세의 기술 스택 표만 패널/테두리를 씁니다. 대외활동·수상·학회·학력·연락처 같은 이력은 줄로만 나눈 평범한 행입니다.
4. **컴포넌트로 조립한다.** 몇 개의 컴포넌트가 모든 페이지를 만들고, 프로젝트 상세는 각 프로젝트가 가진 데이터로 블록을 고릅니다(아래 "프로젝트 상세").

남은 도형은 기능이 있는 것뿐입니다: 기술 노드(테두리 상자), 배포 중 점, 자리표시의 점선, GitHub 마크, 현재 위치 막대(2px).

- 기본 규칙: `h1–h3 { text-wrap: balance }`, `a, button, summary { touch-action: manipulation }`, 탭 하이라이트 없음(대신 `:focus-visible` 링과 `active:` 상태), `img`는 로딩 중 `surface` 바탕.
- 커스텀 변형 `tiny:` = `max-height: 240px`(400% 확대 — 이때만 헤더 고정을 풉니다). `shell` = 최대 1240px, 좌우 16/24/40px.

- **기술 표시는 한 가지 방식**: 분류 라벨(muted) + 칩(목록 항목) 또는 노드(링크: 지도·목록 필터·상세 머리), 분류 순서는 어디서나 `언어 → 프론트엔드 → 모바일 → 백엔드 → AI → DB → 데이터 → 인프라 → 도구 → 기타`. 정적 칩(`rounded-tag`, `line` 테두리)과 누를 수 있는 노드(`rounded-node`, `edge` 테두리, 개수 배지)는 모양으로 구분됩니다 — **노드 = 링크, 칩 = 라벨**. 긴 영어 이름은 줄바꿈되도록 고정 높이 대신 `min-h-*`.
- **링크는 한 가지 모양**: `primary` + 밑줄(hover에 굵어짐). 항목 제목(카드 전체 링크)만 예외로 ink, hover에 primary.

## 홈

1. **첫 줄 (1024 이상 7/5, 그 아래는 위아래)**: `IdentityBlock`(3:4 사진 — 휴대폰 96px · 태블릿 144px · 1024 128px · 1280 이상 200px, 이름 + 다른 언어 이름 · 역할 · 소개 · 사실 4줄: 소속 / 학회(→ `#society`) / 이메일 + 복사 / GitHub) | `StackMap`(좁은 열에서는 분류 라벨이 노드 위로).
2. **기술 스택 지도** (`#skills`, 내비 2번째 "기술 스택"): `skills.json`의 분류마다 한 줄, 기술마다 노드 하나. 노드에 사용 횟수 숫자는 **표시하지 않습니다**(주인 결정). 순서는 `skills.json`에 적힌 순서. 스크린 리더용 문구는 "이 기술을 쓴 프로젝트 보기". 어떤 프로젝트에도 없는 기술(예: TypeScript)은 점선 노드 + "기록된 프로젝트 없음", 그런 노드가 있을 때만 범례 한 줄. 막대·별점·%·채운/빈 칸은 **쓰지 않습니다**(숙련도로 읽힘).
3. **기술로 거르기**: 노드는 진짜 링크입니다. JS 없이는 `/[locale]/projects/tech/<slug>/`(정적 페이지, 시안에서는 목록 `?tech=`)로 가고, JS가 있으면 홈 목록을 그 자리에서 거릅니다: 맞는 항목만 남고 그 칩이 `primary-100`, 노드는 `aria-current="true"`, URL에 `?tech=<slug>`, 필터 바 "Next.js 사용 프로젝트"(개수 없음) + "필터 해제", 결과는 `role="status"`로 알림(키보드로 고르면 대신 결과 문장(`tabindex="-1"`)으로 포커스가 가고, 다음 Tab이 "필터 해제"). 같은 노드를 다시 누르거나 "필터 해제"로 풀고, 해제하면 그 노드로 포커스가 돌아갑니다.
4. **프로젝트** (`#projects`): 제목 + 개수 + 목록 링크(홈에 다 보이면 "프로젝트 목록", 더 있으면 "프로젝트 N개 모두 보기"; 홈은 대표 포함 최대 5개). 모든 항목이 같은 틀: 글 7열(제목·소개·메타, 대표는 핵심 최대 3·관계까지) + 오른쪽 5열(대표는 캡처 → 기술·저장소, 나머지는 기술·저장소). 저장소 이름은 GitHub로 가는 링크이고, 그 링크만 카드 전체 링크 위에 올라갑니다(별·커밋 글자를 눌러도 프로젝트로 감). 목록 아래에 **출처 한 줄**: "별과 최근 커밋은 yyyy.mm.dd 기준 GitHub 값이에요."
5. **대외활동 | 수상** (각 3개, 넘치면 "더 보기 (N)" `<details>`): 제목(+등급 `award`), 기관·역할(가운뎃점 없이 간격), 날짜, 관계 링크.
6. ~~학회~~: 주인 요청으로 삭제. 학회 운영진 이력은 경력으로 씁니다.
7. **학력 및 경력사항 | 연락처**: "학력"·"경력" 소제목 아래 평범한 행(모르는 기간·상태는 비워 둠). 소개 사실 표에 첫 경력이 `#education` 링크로 들어갑니다. 내비 라벨이 길어서 휴대폰 4칸 내비에서 두 칸을 씁니다(`sections.ts`의 `wide`). 연락처 값은 링크 모양, 이메일·Discord에 복사 버튼.

## 프로젝트 상세 — 기본 양식 하나, 블록은 데이터로

**머리**: 이동 경로(터치 영역 44px) → H1 + 한 줄 소개 → 기술(분류별 **노드**: 홈 필터로 가는 링크, 숫자 없음) → 데모 버튼(배포 중이고 URL이 있을 때만) → 사실 표 6칸(기간 · 종류 · 팀 · 역할 · 진행 상태 · 배포). 오른쪽 5열: **대표 캡처**(웹 + 휴대폰, 있을 때만) + "화면 N개 모두 보기", 그 아래 **저장소 카드**(GitHub 링크가 있을 때만: 저장소 이름 링크 · 별 · 최근 커밋 · 라이선스 · "yyyy.mm.dd 기준 GitHub 값이에요."). 휴대폰에서는 제목 → 기술·사실 → 캡처 → 저장소 카드 순(DOM 순서 = 보이는 순서).

**본문**: 왼쪽 sticky 목차 + 블록. 블록은 레지스트리에서 순서대로, **데이터가 있을 때만** 그려지고 목차도 그려진 블록으로만 만듭니다.

- 시안의 두 번째 상세(강의 요약 챗봇)는 같은 양식에 데이터가 적은 경우입니다: 캡처·관계·구조·문제와 해결·결과가 없어서 머리 오른쪽은 저장소 카드만, 본문은 요약 · 내가 한 일 · 핵심 기능 · 기술 스택 · 배운 점 다섯 블록, 목차도 다섯 줄입니다(첫 상세는 열 블록).
- **프로젝트 성격별 양식(나중에)**: 선택 필드 `Project.layout`(지금은 `"default"`만). 새 프리셋은 **블록 순서와 머리 오른쪽에 무엇을 둘지만** 바꿀 수 있고, 색·글꼴·새 컴포넌트는 추가하지 않습니다. 예: 연구형 = 결과·배운 점을 요약 다음으로, 해커톤형 = 결과(수상)를 위로, 기술형 = 구조·기술 스택을 위로. 모르는 값은 `default`로. 팩트시트 프롬프트가 성격을 제안하고 주인이 확인합니다.
- 이전/다음: 최신순으로 이전 = 더 최신, 다음 = 더 오래된 프로젝트. 끝에서는 "프로젝트 N개 모두 보기".

## GitHub 연동

- **데이터 출처는 커밋된 스냅샷 하나**: `scripts/fetch-github.ts`가 `links[type=github]`의 `owner/repo`마다 `GET /repos/{o}/{r}`(별, 기본 브랜치, 보관 여부, 라이선스) · `/languages`(바이트 → %, 상위 4 + 기타) · `/commits?sha={기본 브랜치}&per_page=1`(최근 커밋 날짜)을 받아 `src/data/github-snapshot.json`(`{ fetchedAt, repos }`, zod 검증)에 씁니다. `deploy.yml`에서 빌드 전에 `GITHUB_TOKEN`으로, 실패하면 이전 스냅샷을 그대로 씁니다. **`next build`는 네트워크를 부르지 않습니다.**
- 보여 주는 것: 저장소 이름(GitHub로 가는 링크), 별, 최근 커밋 yyyy.mm, 라이선스, 언어 비율, 기준일. 보관된 저장소는 "보관됨". 값이 없으면 그 칸을 그리지 않습니다(0을 지어내지 않음). 별이 0일 때 숨길지는 주인에게 확인.
- 보여 주지 않는 것: 팔로워, 잔디, 저장소 총수, 포크·워처(변동이 크고 프로젝트의 근거가 아님). 저장소 설명이 팩트시트의 소개를 대신하지 않습니다.
- 비공개 저장소는 팩트시트 단계에서 링크를 넣을지 묻습니다(넣지 않으면 저장소 줄·카드가 없음).

## 프로젝트 화면 (스크린샷)

- **비율은 셋뿐이고 자르지 않습니다**: 웹 `aspect-16/10` · 휴대폰 `aspect-6/13`(≈ 9:19.5) · 사진 `aspect-4/3`. 칸이 비율을 고정하고 이미지는 같은 비율로 준비합니다.
- **자리표시(시안 전용)**: `surface` 바탕 + `ring-1 ring-inset ring-line` + 가운데 "웹 화면 / 16:10" 두 줄. 실제 사이트에서 캡처가 없으면 그 자리 자체를 그리지 않습니다(빈 상자 없음).
- **대표 항목·상세 머리**: 웹 + 휴대폰을 `grid-cols-[minmax(0,208fr)_minmax(0,60fr)]`로 같은 높이에(16:10과 6:13의 높이를 맞춘 비율). 휴대폰만 있으면 휴대폰 하나를 144–192px 폭으로(칸 전체로 늘리지 않음). 상세 머리에서는 640 미만일 때 휴대폰을 빼고 웹을 크게.
- **갤러리**: 넓은 화면(웹·사진)마다 휴대폰을 두 장까지 붙여 한 줄(`208fr 60fr 60fr`), 남은 넓은 화면은 둘씩(`grid-cols-2`), 하나만 남으면 반 폭, 남은 휴대폰은 한 줄에 4장. 640 미만은 넓은 화면 한 줄, 휴대폰 2열. 각 화면은 `<figure>` + 캡션(종류 + 설명). 4장을 넘으면 나머지는 "화면 더 보기 (N)" `<details>`, "화면 N개 모두 보기"는 그것도 펼칩니다.
- **원본 보기**: 상세의 캡처는 실제 사이트에서 원본 파일로 가는 링크(`<a target="_blank" class="block cursor-zoom-in">` + `<span class="sr-only">원본 크기로 보기</span>`, 새 탭 안내). 따로 그리는 아이콘은 없습니다.

## 구현 시 지켜야 할 동작

1. **날짜**: `formatYm("2025-03") → "2025.03"`, 기간 `2025.03 – 2025.06`(en dash, NBSP), 끝이 없으면 `현재`/`Present`, 재학 `재학 중`/`Enrolled`. 어디서나 최신순.
2. **홈 개수 제한**: 프로젝트 = 대표(없으면 최신) 포함 최대 5개, 나머지는 "모두 보기"(목록)로 · 활동/수상/행사 = 3 + 더 보기. 내용이 없는 섹션도 제목과 "아직 등록된 내용이 없어요." 한 줄로 보여 줍니다(주인 요청 2026.10 — 내용 없이 디자인을 먼저 공개). 내용이 생기면 자동으로 채워집니다.
3. **관계**: DOM id = 내용 id. 무방향, 양쪽 모두에 링크. 내용에 적힌 관계만(추측 금지). 프로젝트 → 상세, 나머지 → 홈의 `#id`. 접힌 `<details>` 안을 가리키면 열어 줍니다.
4. **스크롤스파이**: 기준선 = 헤더 아래 끝 + 24px. 기준선을 지난 마지막 섹션이 현재. 나란한 두 섹션(같은 top)은 앞의 것, 단 다른 쪽을 클릭했다면 그것. 클릭한 링크는 점프가 끝날 때까지(`scrollend`, 없으면 2.5초) 유지되고, 페이지 맨 아래까지 못 올라오는 섹션도 클릭했다면 유지. 현재 링크는 `aria-current="location"` + `data-current="true"` **하나만**. 상세 목차도 같은 방식.
5. **상태 속성은 값으로**: `data-current="true"`, `data-show="false"`, `data-match="true"`, `data-done="fail"`처럼 값을 넣고 `data-[show=false]:hidden` 식으로 선택합니다.
6. **복사 버튼**: 28px + `after:-inset-2`(44px 터치). "복사" → "복사됨"(`live`, 1.6초). 클립보드가 막히면 "복사 실패"(`award`, 4초) + "선택된 글자를 직접 복사해 주세요" + 값 글자 선택. 결과는 `role="status"` 하나로.
7. **터치**: hover가 없는 기기를 위해 누를 수 있는 것마다 `active:` 상태. 헤더 언어 링크는 `after:`로 터치 영역 확장.
8. **접근성**: 페이지당 H1 하나 · 랜드마크(header, nav×2 같은 이름 — 브레이크포인트마다 하나만 보임, main, footer) · 건너뛰기 링크 · 외부 링크 "(새 탭)" · 기술 이름 `translate="no"` · 장식은 `aria-hidden` · 고대비 모드에서 현재 표시 `forced-colors:bg-[CanvasText]`, 현재 언어 밑줄 · 카드 전체 링크는 `has-[[data-stretch]:focus-visible]:outline-2`.
9. **사실만**: 시안의 홍길동 내용은 가짜 예시입니다. 모르는 값은 `[역할]`, `[★ 수]` 같은 괄호 자리표시이고 실제 사이트에서는 그 요소를 그리지 않습니다.
10. **이미지 포팅**: 정적 내보내기라 기본 이미지 로더 없음 — `<img width height alt loading="lazy" decoding="async">`, 상세 머리의 대표 캡처 하나만 `fetchpriority="high"`. WebP/AVIF, GIF 금지(움직이는 화면이 필요하면 주인에게 먼저 묻고 `<video muted playsinline>` + `prefers-reduced-motion`에서 정지).

- **2차 검토(같은 스킬 3개 + 반박 검증, 확인 23건 · 기각 7건)에서 고친 것**: 프로젝트마다 저장소 이름을 GitHub 링크로(이전에는 글자뿐, 카드 위에서 누를 수 없는 줄) · 두 번째 상세가 정말 적은 블록만 그리도록(구조·문제와 해결·결과는 데이터가 있을 때만) · 키보드로 기술을 고르면 결과 문장으로 포커스 · 상세에서 기술 스택과 수상이 두 번 나오던 것 정리(머리 = 노드, 블록 = 겹치는 프로젝트 + 언어 비율, 관련 항목은 결과에 나온 수상 제외) · 1024에서 첫 화면 7/5로(프로젝트가 더 빨리 보임) · 대표 항목도 기술·저장소를 오른쪽 열에 · 이중 구분선 제거 · 확대 칩 제거 · 긴 영어 기술 이름이 넘치지 않게 · 영어 복수형 · 이동 경로 터치 영역 · 휴대폰 상세에서 사실 표를 캡처보다 먼저 · 부드러운 스크롤 제거 · "모두 보기"가 이미 다 보일 때 "프로젝트 목록"으로 · 문구(출처 한 줄을 쉬운 말로, EN "Tech stack", "Type").

## 시안 다시 만들기

`mockup/`은 작업 폴더 구조 그대로입니다(`sys/` = 생성기·스크립트, `proto/` = 테마와 출력).

1. 글꼴: `pretendard` npm 패키지의 `PretendardVariable.woff2`를 `mockup/design/fonts/`에 둡니다(커밋하지 않음).
2. `python3 mockup/sys/gen.py proto` → `mockup/proto/sys-{home,detail,detail2,list}-{ko,en}/index.html`
3. `cd mockup/proto && npx @tailwindcss/cli@4 -i sys-input.css -o sys.css` (캔버스용은 `--minify` 후 `python3 ../sys/flatten.py <입력> <출력>` — 캔버스 런타임의 CSS가 Tailwind 레이어를 이기지 못하게 `@layer`를 풉니다)
4. `node mockup/sys/shoot.mjs` (스크린샷 + 높이·글자 크기·날짜 감사), `node mockup/sys/verify.mjs` (위 검증표 전체), `python3 mockup/sys/scen.py && (cd mockup/proto && npx @tailwindcss/cli@4 -i _scen-input.css -o _scen.css) && node mockup/sys/scen.mjs` (화면 경계 사례)
5. 캔버스: CSS를 캔버스 자산으로 올리고 `python3 mockup/sys/gen.py dc /_blob/<id> mockup/design2` → `canvas.json`과 아트보드를 게시.
