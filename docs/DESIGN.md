# DESIGN.md — 비주얼 디자인과 디자인 시스템

## 이 사이트가 주는 인상

포트폴리오의 독자는 **학회 심사위원과 채용 담당자**다. 짧은 시간에 훑는다.
따라서 목표는 "화려함"이 아니라 **읽히는 것**이다.

- 정보 위계가 첫눈에 보인다 (무엇을 만들었나 → 어떤 역할이었나 → 결과가 무엇인가)
- 스크롤 없이 첫 화면에서 "이 사람이 누구인지"가 파악된다
- 인쇄/PDF로 저장해도 무너지지 않는다 (심사자는 종종 그렇게 본다)

공개 모드와 관리자 모드는 **의도적으로 다르게 생겼다**. 공개 화면은 작품, 관리자 화면은 도구다.
관리자 모드는 밀도 높고 실용적으로 — 예쁘게 만드는 데 시간을 쓰지 않는다.
둘이 **같은 앱 안에 있으므로**, 모드가 바뀐 것이 한눈에 보여야 한다 (예: 상단 표시줄).

## shadcn/ui 사용 규범 (INV-6)

shadcn은 라이브러리가 아니라 **코드 생성기**다.

1. 컴포넌트 추가는 CLI로만: `npx shadcn@latest add <name>` (→ `/add-ui-component` 스킬)
2. 생성물(`src/shared/ui/components/ui/**`)은 **손으로 고치지 않는다.** 훅이 편집을 차단한다
3. 커스터마이즈가 필요하면:
   - 색·간격·라운드 → `tailwind` 테마 토큰에서
   - 동작·조합 → `src/shared/ui/`에 **래퍼 컴포넌트**를 만든다
   - 그래도 안 되면 ADR을 쓰고 생성물을 fork 한다 (마지막 수단)
4. 생성된 컴포넌트를 앱에서 직접 import 하지 않는다. `src/shared/ui`의 배럴을 통한다

## 토큰

색·타이포·간격은 **Tailwind 테마 토큰으로만** 표현한다.
컴포넌트 안에 하드코딩된 hex, `px` 매직넘버 금지 — 린트가 잡는다.
다크 모드는 토큰 레벨에서 해결하고, 컴포넌트에 조건 분기를 넣지 않는다.

## 접근성 (GR-7)

- 시맨틱 태그 우선 (`<nav>`, `<main>`, `<article>`, `<time>`)
- 모든 인터랙티브 요소는 키보드로 도달·조작 가능
- 본문 대비 4.5:1 이상, 큰 텍스트 3:1 이상
- 모든 이미지에 의미 있는 `alt` (장식이면 `alt=""`)
- 포커스 링을 제거하지 않는다

`/ui-verify`가 렌더 결과에서 이 항목들을 점검한다.

## 관리자 모드의 시각 규칙

- **관리자 모드임이 항상 보여야 한다.** 공개 화면과 구분되지 않으면 실수로 편집하게 된다
- 파괴적 동작(삭제, 게시)은 시각적으로 무게가 있어야 한다
- 게시 후 **공개 반영까지 시간이 걸린다는 것**을 화면이 알려준다 ([ADR-0003](design-docs/adr/0003-content-store.md))
- 토큰 입력란은 마스킹하고, 입력한 값을 다시 표시하지 않는다 ([SECURITY.md §3](SECURITY.md))
