# PLANS.md — 계획 규범

계획은 **일급 아티팩트**다 (CB-4). 대화에만 남은 계획은 존재하지 않는 계획이다.

## 언제 문서 계획을 쓰는가

| 상황 | 계획 형태 |
|---|---|
| 파일 1~2개, 되돌리기 쉬움 | 즉흥 계획. 문서 불필요 |
| 파일 3개 이상 / 새 도메인 / 레이어 경계 변경 | `docs/exec-plans/active/`에 실행 계획 문서 |
| 아키텍처·스택·저장 방식 변경 | 실행 계획 **+** ADR |

판단이 애매하면 쓴다. 계획을 쓰는 비용보다 컨텍스트를 잃는 비용이 크다.

## 실행 계획의 수명

```
active/NNNN-slug.md  ──작업 진행──▶  체크박스 갱신 + 결정 로그 누적
        │
        ├─ 완료 ──▶ completed/NNNN-slug.md 로 이동, index.md 갱신
        └─ 미완의 잔재 ──▶ tech-debt-tracker.md 에 항목 등록
```

**계획을 완료 처리하기 전에 반드시**: 잔여 작업이 `tech-debt-tracker.md`에 남았는지 확인한다.
말없이 사라진 항목이 드리프트의 시작이다.

## 결정 로그

계획 실행 중 내린 판단은 계획 문서 하단 **결정 로그**에 날짜와 함께 남긴다.
"왜 A 대신 B로 갔는가"가 다음 에이전트의 시간을 가장 많이 절약한다.
결정이 계획 하나를 넘어 지속되면 ADR로 승격한다.

## 도구

`/exec-plan` 스킬이 번호 채번, 템플릿 채우기, 색인 갱신, 완료 이동을 처리한다.
