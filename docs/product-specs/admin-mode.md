# 스펙: 관리자 모드

- **상태**: DRAFT — **사용자 입력 필요**
- **대상**: 본인 단독
- **관련**: [ADR-0004](../design-docs/adr/0004-single-app-admin-mode.md), [ADR-0003](../design-docs/adr/0003-content-store.md), [SECURITY.md](../SECURITY.md)

## 성공 기준

**포트폴리오가 낡지 않게 유지되는 것.** 편집이 번거로우면 콘텐츠가 낡고, 제품은 실패한다.

## 전제 — 반드시 먼저 읽을 것

관리자 여부를 **앱이 판정하지 않는다. GitHub 이 판정한다.**
UI 를 숨기는 것은 보안이 아니다. 실제 경계는 토큰 검증이다. → [SECURITY.md §1](../SECURITY.md)

## 사용자에게 확인해야 할 것

- [ ] 관리자 모드 진입점을 어디에 둘 것인가? (`/admin` 경로 / 푸터 링크 / 키보드 단축키)
- [ ] 토큰을 이 기기에 기억하는 옵션이 필요한가? (편의 ↔ 위험)
- [ ] 어떤 종류의 글을 쓰는가? (프로젝트 리뷰 / 회고 / 기술 글 — 각각 다른 스키마인가?)
- [ ] 이미지 업로드가 필요한가? 어느 정도 크기·개수인가?
- [ ] 초안(비공개 저장) 상태가 필요한가?

## 동작 (가설)

| # | 동작 | 기대 결과 |
|---|---|---|
| A-1 | 관리자 모드 진입 | 토큰 입력을 요구한다. 토큰은 마스킹되고 다시 표시되지 않는다 |
| A-2 | 토큰 검증 | GitHub 에 실제 권한을 확인한다. 실패 시 이유를 분명히 알려준다 |
| A-3 | 검증 성공 | 관리자 UI 가 열린다. 세션 종료 시(탭 닫기) 자동으로 잠긴다 |
| A-4 | 항목 목록 보기 | 모든 콘텐츠를 종류별로 훑을 수 있다 |
| A-5 | 항목 생성/수정 | 스키마 기반 폼. 잘못된 값은 **커밋 전에** 막힌다 |
| A-6 | 글쓰기 (프로젝트 리뷰 등) | 마크다운 작성 + 미리보기. 미리보기는 공개 화면과 같게 렌더된다 |
| A-7 | 게시 | GitHub 에 커밋한다. 성공/실패가 분명히 보인다. 실패 시 입력값이 남는다 |
| A-8 | 반영 지연 안내 | 공개 반영까지 재배포 시간(~1분)이 걸린다는 것을 알려준다 |
| A-9 | 충돌 | 다른 곳에서 먼저 수정됐으면 **덮어쓰지 않고** 사용자에게 알린다 |
| A-10 | 순서 변경 / 공개 여부 | 표시 순서와 노출 여부를 제어할 수 있다 |
| A-11 | 삭제 | 확인을 거친다. git 이력으로 복구 가능함을 안내한다 |
| A-12 | 로그아웃 | 토큰을 즉시 지운다 |

## 하지 않는 것

- 다중 사용자, 권한 관리, 협업 편집
- 자체 비밀번호·계정 시스템 (**보안이 되지 않는다** — [SECURITY.md §1](../SECURITY.md))
- 예쁜 디자인 (PRODUCT_SENSE: 관리자 모드는 도구다)
