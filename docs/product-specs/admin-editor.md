# 스펙: admin — 포트폴리오 편집 도구

- **상태**: AGREED
- **대상**: 본인 단독, **로컬 전용**
- **관련**: [ADR-0003](../design-docs/adr/0003-content-store.md), [SECURITY.md](../SECURITY.md)

## 성공 기준

**포트폴리오가 낡지 않게 유지되는 것.** 편집이 번거로우면 콘텐츠가 낡고, 제품은 실패한다.

## 전제 — 로컬 전용 (사용자 결정, 2026-09-06)

admin 은 **본인 컴퓨터에서 개발 서버로만 실행**한다. 공개 URL 에 올리지 않는다.

그래서 **자격 증명이 존재하지 않는다.** 토큰도, 비밀번호도, 로그인 화면도 없다.
쓰기 경계는 "이 컴퓨터에서 `npm run dev:admin` 을 띄울 수 있는가" 하나다.

쓰기는 **개발 서버 미들웨어**가 `content/` 에 직접 한다.
미들웨어는 개발 서버에만 존재하며 어떤 빌드 산출물에도 포함되지 않는다 ([ADR-0003](../design-docs/adr/0003-content-store.md)).

## 동작

| # | 동작 | 기대 결과 |
|---|---|---|
| E-1 | 항목 목록 | 논문 리뷰·프로젝트·블로그 글·스펙을 종류별로 훑을 수 있다 |
| E-2 | 생성/수정 | **필드별 폼.** 날짜는 달력, 태그·저자는 칩, 분류는 선택지, 본문은 마크다운 |
| E-2b | 검증 | 잘못된 값은 **저장 전에** 막힌다. 오류는 필드 이름과 함께 한국어로 (INV-3) |
| E-2c | id 고정 | 새 항목에서만 입력받는다. 저장한 뒤에는 **잠긴다** (→ [id 는 왜 못 바꾸나](#id-는-왜-못-바꾸나)) |
| E-3 | 저장 | `content/` 파일에 쓴다. 성공/실패가 분명히 보인다 |
| E-4 | 저장 실패 | **입력값이 남는다.** 원인을 구분해 알린다 (검증 실패 / 쓰기 실패) (GR-4) |
| E-5 | 순서·공개 여부 | viewer 에 보이는 순서와 노출을 제어한다 |
| E-6 | 삭제 | 편집 패널 안에서만. 확인 모달이 **제목**을 보여준다 (→ [삭제](#삭제)) |
| E-7 | 미리보기 | **로컬 viewer 를 띄우면 그것이 정확한 미리보기다.** 별도 구현 없이 안내만 한다 |

## 스키마를 바꿨다면 admin 을 재시작한다

쓰기 미들웨어는 **개발 서버가 시작될 때 스키마를 읽는다** (vite.config 에서 Node ESM 으로 로드).
스키마를 고치고 서버를 그대로 두면 화면의 선택지는 새 값인데 저장이 422 로 거부된다.

- 증상: 폼에는 새 분류가 보이는데 저장하면 "스키마 검증에 실패했습니다"
- 해결: `npm run dev:admin` 재시작 (viewer 는 HMR 로 알아서 반영된다)

## id 는 왜 못 바꾸나

`id` 는 두 가지를 동시에 결정한다: **공개 URL** (`/projects/<id>`) 과 **파일 이름**
(`content/projects/<id>.json`). 그래서 한 번 저장하면 잠근다 (2026-09-08 결정).

바꿀 수 있게 두면 저장 경로가 새 id 로 파일을 쓰고 **원본은 그대로 남는다.**
같은 항목이 둘이 되고, 이미 나간 링크는 404 가 된다. 사용자가 알아채기 어렵다.

강제는 두 겹이다:

1. **화면** — 기존 항목을 열면 입력이 disabled 이고 `고정 · 바꿀 수 없음` 이 붙는다
2. **저장 경로** — `toPayload` 가 `immutable` 필드를 원래 값으로 되돌린다.
   화면을 우회해도 바뀌지 않는다 (`use-form.test.ts`)

정말 바꿔야 한다면 새로 만들고 예전 항목을 지우는 게 맞다 — 그게 링크가 깨진다는
사실을 드러내기 때문이다.

## 삭제

삭제 버튼은 **편집 패널 안에만** 있다 (EP-0003). 목록 카드마다 두면 오클릭이 난다.

| # | 상황 | 기대 결과 |
|---|---|---|
| D-1 | 삭제 클릭 | `AlertDialog` 로 확인을 받는다. **제목**을 보여준다 — 파일명이 아니다 |
| D-2 | 확인 | 파일이 지워지고, 패널이 닫히고, 목록·게시 건수가 갱신된다 |
| D-3 | 프로필 | **삭제 버튼이 없다.** 프로필은 하나뿐이고, 없으면 Hero·About 가 빈 화면이 된다 |
| D-4 | 새 항목 (저장 전) | 삭제 버튼이 없다 — 지울 대상이 없다 |
| D-5 | 실패 | 저장 실패와 구분해 알린다 (GR-4) |

**되돌리기는 화면에 없다.** 두 단계로 안전을 확보한다:

1. 게시하기 전까지 공개 사이트는 그대로다 — 모달이 이 사실을 알려준다
2. 이미 게시했다면 git 이력에 남아 있다 → `git revert <커밋>`

게시 모달은 삭제된 항목도 **제목**으로 보여준다. 삭제하면 작업트리에 파일이 없으므로,
미들웨어가 `git show HEAD:<경로>` 로 마지막 커밋에서 제목을 꺼내 실어 보낸다.
꺼내지 못하면 id 로 대신하고 게시를 막지 않는다.

## 게시

배너의 **게시** 버튼이 `content/` 를 커밋하고 푸시한다. CI 가 빌드해 약 45초 뒤 공개된다.

| # | 동작 | 기대 결과 |
|---|---|---|
| P-1 | 미게시 변경 있음 | 버튼에 건수가 보인다 |
| P-2 | 미게시 변경 없음 | 버튼이 비활성이다 |
| P-3 | 게시 클릭 | 무엇이 올라가는지 **제목으로** 보여주고 확인을 받는다 |
| P-4 | 성공 | 커밋 요약과 반영 예상 시간을 알린다 |
| P-5 | 실패 | 원인을 구분한다 (충돌 / 인증 / 원격 없음) |
| P-6 | 항목별 게시 | 그 항목만 커밋·푸시한다. **나머지는 미게시로 남는다** |
| P-7 | 항목별 복구 | 그 항목만 되돌린다. 확인을 거친다 (→ [복구](#복구)) |
| P-8 | 항목 작업 중 | **그 줄의 버튼만** 잠긴다. 다른 줄은 계속 누를 수 있다 |

### 경로를 신뢰하지 않는다

항목별 작업의 대상 경로는 화면에서 온다. 그대로 git 에 넘기면 `content/` 밖을
건드릴 수 있다. `startsWith('content/')` 같은 문자열 검사는 `content/../..` 를 놓친다.

그래서 **git 이 실제로 보고한 미게시 변경 목록과 대조**한다 (`resolveTargets`).
목록에 없는 경로가 하나라도 섞이면 요청 전체를 거부한다.

## 복구

미게시 변경을 마지막 게시 상태로 되돌린다.

| 동작 | 복구하면 |
|---|---|
| 추가 | 항목이 사라진다 (한 번도 게시된 적 없음) |
| 수정 | 마지막으로 게시한 내용으로 돌아간다 |
| 삭제 | 지운 항목이 되살아난다 |

**삭제보다 위험하다.** 게시된 항목은 git 에 남아 `git revert` 로 되살릴 수 있지만,
아직 게시하지 않은 편집은 어디에도 없다 — 복구하면 그 작업은 영영 사라진다.
그래서 삭제와 달리 **동작별로 무엇이 없어지는지** 말해주고 확인을 받는다.

구현 주의: 추적되지 않는 새 파일은 `git rm` 이 조용히 아무 일도 하지 않는다.
git 이 모르는 파일이므로 직접 지운다 (`revertOne`).

## 하지 않는 것

- 다중 사용자, 권한 관리, 협업 편집
- 로그인·인증 (로컬 전용이므로 불필요)
- 자동 푸시 — 저장과 공개는 분리한다 ([ADR-0003](../design-docs/adr/0003-content-store.md))
- 예쁜 디자인 — admin 은 도구다 (PRODUCT_SENSE)
- viewer 의 코드를 복제 — 공유가 필요하면 `shared/` 로 올린다 (INV-9)
