# RELIABILITY.md — 빌드, 배포, 복구

## 배포 대상

GitHub Pages. 저장소 `gaudium1257/gaudium1257.github.io`.

| 앱 | 배포 |
|---|---|
| `viewer` | **공개 배포.** 사이트 루트 |
| `admin` | **배포하지 않는다.** 로컬 전용이다 ([ADR-0003](design-docs/adr/0003-content-store.md)) |

admin 은 CI 빌드 대상이 아니다. 공개 경로에 올리려면 [SECURITY.md](SECURITY.md) 재검토 + 새 ADR 이 필요하다.

**게시는 git push 다.** admin 은 `content/` 파일을 고칠 뿐, 게시하지 않는다.

배포 소스는 **GitHub Actions** 로 설정한다 (Settings → Pages → Source: GitHub Actions).
빌드 산출물을 커밋하지 않는다 — 소스와 `content/` 만 커밋한다.

## 파이프라인

```
push(main) → verify → viewer 빌드 → 공개 번들 검사(INV-8) → Pages 배포
```

워크플로는 두 개다:
- `.github/workflows/verify.yml` — 모든 브랜치·PR 에서 검증만
- `.github/workflows/deploy.yml` — main 에서만 빌드·배포

**admin 은 빌드 대상이 아니다.** 배포 단계에 공개 번들이 admin 쓰기 경로를
포함하지 않는지 확인하는 검사가 들어 있다 (INV-8).

`verify` 가 실패하면 배포하지 않는다. **이것이 유일한 차단 게이트다.**

## 딥링크 (스펙 C-3)

Pages 는 정적 파일만 서빙한다. `/projects/foo` 에 파일이 없으면 404 다.

`404.html` 폴백만 두면 화면은 뜨지만 **HTTP 상태가 404** 라 크롤러와 링크 미리보기가
깨진 링크로 취급한다. 포트폴리오 링크를 심사자에게 보내는 사이트에서는 문제다.

→ **콘텐츠 id 는 빌드 타임에 알 수 있으므로 라우트별 정적 파일을 생성한다.**
`404.html` 은 진짜 없는 경로를 위해 남긴다.

## 머지 철학

에이전트 처리량이 사람의 주의력을 넘어서면, **긴 차단 게이트가 오히려 비용**이 된다.

- PR 은 짧게 산다. 큰 변경은 나눈다
- 차단 게이트는 `verify` 하나로 유지한다. 게이트를 늘리기 전에 정말 필요한지 묻는다
- 고치는 비용이 싸고 대기 비용이 비싸면, 후속 수정으로 해결한다
- 단, **되돌리기 어려운 것**은 앞에서 막는다:
  - 공개된 개인정보 (검색엔진이 이미 가져갔다고 가정한다)
  - 유출된 토큰 (되돌리기가 아니라 **폐기**가 답이다)

## 실패했을 때

1. **되돌린다.** 원인 분석보다 복구가 먼저다. 정적 사이트라 이전 커밋으로 되돌리면 끝이다
2. 재현되는 최소 케이스를 만든다
3. 고치고, **회귀 테스트를 추가한다**
4. 같은 실패가 반복 가능했던 이유를 `docs/` 나 린트 규칙에 인코딩한다 (CB-9)

## 관측

정적 사이트라 서버 로그가 없다. 에이전트가 볼 수 있는 신호는:

- 브라우저 콘솔 에러 / 네트워크 실패 (`/ui-verify` 가 수집)
- **HTTP 상태 코드 실측** — 화면이 떠도 상태가 틀릴 수 있다
- GitHub Actions 빌드 로그
- 테스트 결과

**콘솔 에러가 남은 상태를 "정상"으로 보고하지 않는다** (GR-4).
