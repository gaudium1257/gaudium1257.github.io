# ADR-0004: 단일 앱 + 인증 게이트 관리자 모드

- **상태**: ACCEPTED
- **날짜**: 2026-09-06
- **대체**: [ADR-0001](0001-stack.md) (viewer/admin 분리 모노레포)
- **관련**: [ADR-0003](0003-content-store.md), [docs/SECURITY.md](../../SECURITY.md)

## 맥락

리포지터리 `github.com/gaudium1257/gaudium1257.github.io` 전체가 곧 공개 웹사이트다 (GitHub Pages).
관리 도구를 별도 앱으로 두지 않고, **공개 사이트 안에서 본인임을 인증하면 관리자 모드로 전환**되어
프로젝트 리뷰·글쓰기 등 편집 기능을 쓸 수 있어야 한다.

여기서 피할 수 없는 사실이 하나 있다:

> **정적 사이트에는 서버가 없다. 따라서 클라이언트가 판정하는 인증은 인증이 아니다.**

번들에 넣은 비밀번호·해시·토큰은 누구나 읽을 수 있고, `if (isAdmin)` 분기는 devtools 로 우회된다.
"관리자 UI 를 숨기는 것"으로는 아무것도 지켜지지 않는다.

## 검토한 선택지

| 선택지 | 장점 | 단점 |
|---|---|---|
| 클라이언트 비밀번호 검사 | 구현이 쉬움 | **보안이 아니다.** 번들에서 읽히고 우회된다. 쓰기 대상도 없다 |
| 별도 백엔드/BaaS 인증 | 진짜 세션 관리 | GitHub Pages 에서 못 돌린다. 다른 호스팅과 요금이 따라온다 |
| **GitHub 을 인증 주체로 (채택)** | 권한 판정을 GitHub 이 한다. 서버 불필요 | 자격 증명이 브라우저에 잠시 존재. 리포 범위 관리 필요 |

## 결정

**관리자 여부를 앱이 판정하지 않는다. GitHub 이 판정한다.**

1. 사이트는 **하나의 React 앱**이다. 워크스페이스 분리를 폐기한다 (ADR-0001 대체).
   - `src/domains/portfolio/` — 공개 열람
   - `src/domains/admin/` — 인증 게이트 + 편집. **모든 쓰기 경로는 이 도메인 안에만 존재한다**
2. 관리자 모드 진입은 **GitHub 파인그레인드 PAT** 을 사용자가 런타임에 입력하는 것으로 시작한다.
   토큰 범위는 **이 리포지터리 하나, `contents: read/write` 만**이다.
3. 앱은 그 토큰으로 GitHub API 를 호출해 **실제 쓰기 권한이 있는지 확인**한다.
   이 왕복이 진짜 인증이다. 통과하면 관리자 UI 를 연다.
4. 편집 결과는 GitHub Contents API 로 **리포지터리에 커밋**된다 (→ [ADR-0003](0003-content-store.md)).
5. 토큰은 기본적으로 **`sessionStorage`** 에만 둔다 (탭을 닫으면 사라진다).
   "이 기기에서 기억"은 경고를 동반한 명시적 옵트인으로만 제공한다.
6. **어떤 자격 증명도 리포지터리나 빌드 산출물에 들어가지 않는다** (INV-8).

관리자 UI 를 코드 스플리팅으로 분리하는 것은 성능 목적이지 보안 목적이 아니다. 혼동하지 않는다.

## 결과

**좋아지는 것**
- 서버 없이 진짜 권한 경계가 생긴다. 토큰이 없으면 API 호출이 GitHub 에서 거부된다
- 앱 하나라 스키마·컴포넌트·라우팅이 갈라지지 않는다. 미리보기가 곧 실제 화면이다
- 콘텐츠가 커밋되므로 이력·롤백·diff 가 공짜다

**나빠지는 것 / 감수하는 것**
- 관리자 UI 의 존재는 공개된다. 숨기는 것에 의존하지 않는다
- **XSS 한 방이면 토큰이 털린다.** 서드파티 스크립트 금지, 마크다운 렌더 새니타이즈, CSP 를 지켜야 한다
- 토큰 입력이 매 세션 필요하다 (의도된 비용)
- 편집 후 공개 반영까지 Pages 재배포 시간(~1분)이 걸린다

**강제 수단**
- INV-8: 번들·리포지터리에 자격 증명 리터럴 금지 — 훅 + `lint:arch`
- INV-11: GitHub 쓰기 호출은 `domains/admin/` 밖에 존재할 수 없음 — `lint:arch`

## 되돌리는 조건

- 본인 외 편집자가 생기면 (권한 분리 필요) → 실제 백엔드가 있는 호스팅으로 이전하는 ADR 을 쓴다
- PAT 취급이 부담스러워지면 → OAuth 프록시(서버리스 함수) 도입 ADR 을 쓴다. 토큰 수명이 짧아진다
