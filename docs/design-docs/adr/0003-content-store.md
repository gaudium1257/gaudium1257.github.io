# ADR-0003: 콘텐츠 저장 방식과 게시 경로

- **상태**: ACCEPTED
- **날짜**: 2026-09-06
- **관련**: [ARCHITECTURE.md §2](../../../ARCHITECTURE.md), [SECURITY.md](../../SECURITY.md), [admin-editor.md](../../product-specs/admin-editor.md)

## 맥락

admin 에서 편집한 콘텐츠(논문 리뷰, 프로젝트, 블로그 글)를 viewer 가 읽어야 한다.
호스팅이 GitHub Pages(정적)이므로 서버 런타임도 데이터베이스도 없다.

**사용자 결정: admin 은 로컬 전용이다** (2026-09-06). 공개 URL 에 올리지 않는다.
이 한 가지가 나머지를 전부 단순하게 만든다.

## 검토한 선택지

| 선택지 | 장점 | 단점 |
|---|---|---|
| **A. 로컬 admin 이 파일시스템에 직접 쓰기 (채택)** | **자격 증명이 아예 필요 없다.** 로컬 미리보기가 곧 실제 화면 | 게시에 git push 필요 |
| B. 브라우저가 GitHub API 로 커밋 | 어디서든 편집 | 토큰이 브라우저에 존재 → XSS = 탈취. **로컬 전용이면 얻는 게 없다** |
| C. 외부 헤드리스 CMS / BaaS | 인증·권한 제공 | 무료 티어 의존, 지루하지 않은 기술 (CB-7 역행) |
| D. 로컬 편집 + 전부 수동 | 가장 단순 | admin 이 "웹사이트"인 의미가 옅어짐 |

## 결정

**콘텐츠는 리포지터리의 `content/` 에 JSON 으로 두고, 로컬 admin 이 파일시스템에 직접 쓴다.**

- **읽기 (viewer)**: 빌드 타임에 `content/` 를 번들로 가져온다 (`import.meta.glob`).
  런타임 네트워크 요청이 없다 → 로딩 상태·fetch 실패·CORS 가 전부 사라진다.
  가져온 값은 **경계에서 Zod 로 파싱**한 뒤에만 도메인으로 들어온다 (INV-3)
- **쓰기 (admin)**: admin 의 **Vite 개발 서버 미들웨어**가 `content/` 에 쓴다.
  받은 데이터는 `shared/content` 스키마로 **검증한 뒤에만** 디스크에 쓴다.
  미들웨어는 `apply: 'serve'` 로 개발 서버에만 존재하며 **어떤 빌드 산출물에도 포함되지 않는다**
- **게시**: admin 의 `게시` 버튼이 `git add content/ → commit → push` 를 실행한다.
  CI 가 viewer 를 빌드해 Pages 에 배포한다 (약 45초)

**자격 증명이 존재하지 않는다.** 토큰도, 비밀번호도, 세션도 없다.
쓰기 권한의 경계는 "이 컴퓨터에서 개발 서버를 띄울 수 있는가" 하나다.

## 결과

**좋아지는 것**
- 보안 설계가 대폭 단순해진다. 토큰 저장·유출·폐기 문제가 통째로 사라진다
- 콘텐츠가 git 에 남아 이력·롤백·diff 가 공짜다
- admin 과 viewer 가 같은 `content/` 를 보므로 **로컬 viewer 가 곧 정확한 미리보기**다.
  별도 미리보기 구현이 필요 없다

**나빠지는 것 / 감수하는 것**
- 편집은 이 컴퓨터에서만 가능하다 (의도된 제약)
- 게시에 git push 가 필요하다 — 공개 반영까지 CI 시간이 걸린다
- 여러 기기에서 편집하면 어긋난다. 편집 전 최신 상태인지 확인해야 한다

**강제 수단**
- 쓰기 미들웨어가 빌드에 섞이지 않음: `apply: 'serve'` (프레임워크 보장) + admin 은 배포 대상 아님
- viewer 에 쓰기 경로 금지: INV-8, `lint:arch`
- 앱 소스가 파일시스템을 직접 만지지 않음: `lint:arch` 가 `node:fs` import 를 잡는다
  (파일 접근은 개발 서버 미들웨어의 책임이다)

## 개정 — 게시 자동화 (2026-09-07)

처음에는 'admin 은 게시하지 않는다. 게시는 사용자가 터미널에서 한다' 였다.
터미널을 오가는 게 번거로워 **admin 에 게시 버튼을 두기로** 바꿨다 (사용자 결정).

**저장과 공개는 여전히 분리한다.** 저장할 때마다 자동 푸시하지 않는다 —
오타나 쓰다 만 글이 바로 공개되면 심사자가 보는 사이트에서 사고가 된다.

게시 버튼이 지키는 것:
- 누르기 전에 **무엇이 게시되는지** 보여준다
- `content/` 경로만 커밋한다. 소스 코드는 건드리지 않는다
- 셸에 문자열을 끼워 넣지 않고 **인자 배열로만** 실행한다
- 실패를 구분한다: 변경 없음 / 원격이 앞섬(충돌) / 인증 실패 / 원격 없음

자격 증명은 여전히 존재하지 않는다 — 이미 이 컴퓨터에 설정된 git 자격 증명을 쓸 뿐이고,
admin 이 토큰을 보관하거나 다루지 않는다.
