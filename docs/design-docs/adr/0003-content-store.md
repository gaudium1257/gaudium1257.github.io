# ADR-0003: 포트폴리오 콘텐츠 저장 방식

- **상태**: ACCEPTED (2026-09-06 결정. 자격 증명 방식은 [열린 질문](#열린-질문) 참고)
- **날짜**: 2026-09-06
- **관련**: [ADR-0004](0004-single-app-admin-mode.md), [ARCHITECTURE.md §3](../../../ARCHITECTURE.md), [SECURITY.md](../../SECURITY.md)

## 맥락

관리자 모드에서 작성·편집한 콘텐츠(프로젝트, 리뷰, 글)를 공개 사이트가 읽어야 한다.
호스팅은 GitHub Pages 라 서버 런타임도 데이터베이스도 없다.
[ADR-0004](0004-single-app-admin-mode.md) 에서 **GitHub 을 인증 주체로** 삼기로 했으므로,
같은 토큰으로 같은 리포지터리에 쓰는 것이 자연스럽다.

## 검토한 선택지

| 선택지 | 장점 | 단점 |
|---|---|---|
| **리포지터리에 커밋 (GitHub Contents API) — 채택** | 이력·롤백·diff 공짜. 인증과 저장이 한 메커니즘. 추가 비용 0 | 반영까지 Pages 재배포 대기(~1분) |
| 외부 BaaS (Supabase/Firebase) | 즉시 반영, 진짜 DB | 무료 티어 의존, 공개 API 키 노출, 이중 인증 체계 (CB-7 역행) |
| 브라우저 저장소만 (localStorage) | 가장 단순 | 그 브라우저에서만 보인다. 포트폴리오로서 무의미 |
| 커밋된 JSON 을 런타임 fetch | 재빌드 없이 반영 | Pages 재배포는 어차피 필요. 로딩 상태·실패 경로만 늘어남 |

## 결정

**콘텐츠는 리포지터리의 `content/` 에 JSON 으로 커밋한다.**

- **읽기**: 빌드 타임에 `content/` 를 앱 번들로 가져온다 (`import.meta.glob`).
  런타임 네트워크 요청이 없다 → 로딩 상태·fetch 실패·CORS·API 레이트리밋이 전부 사라진다.
  가져온 값은 **경계에서 Zod 로 파싱**한 뒤에만 도메인으로 들어온다 (INV-3).
- **쓰기**: 관리자 모드에서 GitHub Contents API (`PUT /repos/{owner}/{repo}/contents/...`) 로 커밋한다.
  쓰기 전에 **같은 스키마로 검증**한다. 검증 실패한 값은 커밋하지 않는다.
- **이미지/첨부**: `content/assets/` 에 커밋한다. 업로드 시 클라이언트에서 리사이즈·압축한다.
  리포 용량이 자산이 아니라 부채가 되지 않게 관리한다.
- **반영 경로**: 커밋 → Actions 빌드 → Pages 배포 (~1분). 관리자 UI 는 커밋 직후 낙관적으로 갱신해
  본인에게는 즉시 반영된 것처럼 보이게 한다.

`content/` 의 **데이터**와 `src/shared/content/` 의 **스키마**는 분리한다. 스키마가 단일 진실 원천이고,
읽기·쓰기 양쪽이 같은 스키마를 통과한다.

## 결과

- 좋아지는 것: 콘텐츠가 버전 관리되는 아티팩트가 되어 에이전트도 읽을 수 있다 (CB-1).
  실수로 지운 글이 `git revert` 로 돌아온다. 공개 사이트는 완전 정적이라 빠르고 고장날 것이 없다
- 나빠지는 것: 공개 반영에 재배포 지연이 있다. 콘텐츠 양이 아주 커지면 번들이 커진다
  (수백 개 규모가 되면 라우트별 분할이나 런타임 fetch 로 전환 — 그때 새 ADR)
- 여러 기기에서 편집하면 로컬 캐시가 어긋날 수 있다. 관리자 모드는 **쓰기 전 최신 SHA 를 확인**하고
  충돌 시 덮어쓰지 않고 사용자에게 알린다

## 열린 질문

**자격 증명 방식** — 기본안은 사용자가 파인그레인드 PAT 을 런타임에 입력하고 `sessionStorage` 에 두는 것이다
(ADR-0004 결정). 대안은 서버리스 OAuth 프록시로 수명이 짧은 토큰을 받는 것인데,
GitHub Pages 밖에 함수 하나를 두어야 한다. **사용자 확인 필요** — [tech-debt-tracker TD-001](../../exec-plans/tech-debt-tracker.md).

## 되돌리는 조건

- 콘텐츠 항목이 수백 개를 넘어 번들이 무거워지면 → 런타임 로딩 전환 ADR
- 본인 외 편집자가 생기면 → 실제 백엔드 ADR (ADR-0004 의 되돌리기 조건과 동일)
