# ADR-0005: 표시 레이어를 두 앱이 공유한다

- **상태**: ACCEPTED
- **날짜**: 2026-09-06
- **관련**: [ADR-0001](0001-stack.md), [ADR-0002](0002-layered-architecture.md), [core-beliefs.md](../core-beliefs.md) CB-10

## 맥락

**요구 변경**: admin 이 viewer 와 같은 화면이어야 한다. 별도의 편집기 UI 가 아니라
"공개 사이트에 항목 추가 버튼만 붙은" 모습이다.

지금은 표시 컴포넌트가 전부 `viewer/src/domains/portfolio/` 에 있다.
admin 에서 같은 화면을 내려면 방법이 셋뿐이다.

## 검토한 선택지

| 선택지 | 장점 | 단점 |
|---|---|---|
| admin 이 viewer 를 import | 이동 없음 | 앱 간 직접 참조. 빌드 경계가 무너지고 순환 위험 |
| 컴포넌트를 admin 에 복제 | 당장 빠름 | **한쪽만 고치는 사고가 확정된다** (CB-10). 디자인이 갈라진다 |
| **표시 레이어를 `shared/portfolio` 로 승격 (채택)** | 진실이 하나. 디자인 변경이 양쪽에 자동 반영 | 초기 이동 비용 |

## 결정

**표시에 필요한 것 전부를 `shared/portfolio` 워크스페이스로 옮긴다.**

- 순수 규칙(`service/`): 정렬·공개여부 필터·검색 인덱스·날짜 포맷
- 표시 컴포넌트(`ui/`): 히어로·목록·카드·섹션 제목·마크다운·페이지
- 셸(`app/`): 배너·검색·테마·라우트·레이아웃 폭·디자인 토큰

**두 앱이 다른 것은 두 가지뿐이다.**

| | viewer | admin |
|---|---|---|
| 콘텐츠 출처 | 빌드 타임 `import.meta.glob` | 개발 서버 API (편집 즉시 반영) |
| 편집 기능 | 없음 (INV-8) | 항목 추가·수정 |

페이지 컴포넌트는 **콘텐츠를 props 로 받는다.** 훅을 직접 부르지 않으므로
출처가 달라도 같은 컴포넌트를 쓸 수 있다 (INV-1: ui 는 받은 값을 렌더만 한다).

편집 기능은 **선택적 슬롯**으로 주입한다. viewer 는 아무것도 넘기지 않으므로
공개 번들에 편집 코드가 들어가지 않는다 (INV-8 유지).

## 결과

**좋아지는 것**
- 디자인을 한 번 고치면 양쪽이 같이 바뀐다. 갈라질 수 없다
- admin 에서 보는 것이 곧 공개 화면이다 — 미리보기가 따로 필요 없다
- 정렬·공개여부 규칙이 한 곳이라 "admin 에선 보이는데 공개에선 안 보임" 류의 사고가 사라진다

**나빠지는 것 / 감수하는 것**
- 이동 비용. 임포트 경로가 한 번 크게 바뀐다
- `shared/portfolio` 가 커지면 다시 쪼개야 한다. 지금은 이르다

**강제 수단**
- `lint:arch` 의 레이어 검사를 `shared/<패키지>/<레이어>/` 에도 적용하도록 넓힌다.
  공유로 옮겼다고 레이어 규율이 느슨해지면 안 된다
- INV-8 은 그대로: viewer 에 쓰기 경로가 생기면 린터가 막는다

## 되돌리는 조건

- 두 앱의 화면이 실제로 달라져야 할 이유가 생기면 (예: admin 전용 대시보드)
  그 화면만 앱으로 되돌린다. 공유는 기본값이지 강제가 아니다
