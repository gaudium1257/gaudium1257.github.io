# FRONTEND.md — 프론트엔드 규약

레이어 규칙은 [ARCHITECTURE.md](../ARCHITECTURE.md)에 있다. 여기는 그 안에서의 관례다.

## 컴포넌트

- 함수 컴포넌트 + 명시적 props 타입. `React.FC` 쓰지 않는다
- 파일 하나에 컴포넌트 하나 (내부 전용 소형 하위 컴포넌트는 예외)
- props 가 6개를 넘으면 설계를 다시 본다
- `ui` 레이어에서 데이터 로딩·스키마 파싱 금지 (INV-1). 데이터는 `state` 훅으로 받는다

## 상태 (GR-5)

| 종류 | 두는 곳 |
|---|---|
| 화면 한 곳의 UI 상태 | `useState` — 컴포넌트 로컬 |
| **URL 로 표현 가능한 상태** (검색어, 필터, 탭, 상세 id) | **URL 에 둔다.** 공유·새로고침·뒤로가기가 되어야 한다 |
| 테마 | `shared/providers/` 의 전용 프로바이더 (ADR-0004) |
| 화면 간 공유 클라이언트 상태 | 최소한의 스토어. **도입 전 ADR 로 정당화한다** |

## 데이터 경계 (INV-3)

`data` 레이어 함수는 **파싱된 도메인 타입만 반환**한다.
빌드 타임에 가져온 콘텐츠 JSON 도 예외가 아니다 — `unknown` 으로 받아 스키마를 통과시킨다.
`as` 로 형태를 주장하지 않는다. 파싱 실패는 삼키지 않고 도메인 에러로 변환한다 (GR-4).

**타입은 `shared/content` 에서 가져온다. 앱에서 다시 정의하지 않는다** (INV-9).

## 라우팅

- 라우트 정의는 `app/` 에 모은다. 도메인은 자기가 어느 탭 아래 있는지 모른다
- GitHub Pages 정적 호스팅 제약을 고려한다 (딥링크 새로고침 → 스펙 C-3)

## 성능

포트폴리오는 첫인상이 전부다. 다음만 지키면 충분하다:
- 이미지: 적절한 포맷·크기, `loading="lazy"`, 명시적 width/height (레이아웃 시프트 방지)
- 라우트 단위 코드 스플리팅
- 폰트: 서브셋 + `font-display: swap`
- 조기 최적화 금지. 측정 없이 `memo` 를 뿌리지 않는다

## 폼 (주로 admin)

- 스키마가 진실이다. 같은 Zod 스키마로 검증하고 타입을 뽑는다
- 저장 실패 시 입력값을 잃지 않는다
- 실패는 원인별로 구분해 알린다 (네트워크 / 권한 / 충돌) — 스펙 E-4
- 파괴적 동작(삭제)은 확인을 받는다
