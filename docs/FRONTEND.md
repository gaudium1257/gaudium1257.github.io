# FRONTEND.md — 프론트엔드 규약

레이어 규칙은 [ARCHITECTURE.md](../ARCHITECTURE.md)에 있다. 여기는 그 안에서의 관례다.

## 컴포넌트

- 함수 컴포넌트 + 명시적 props 타입. `React.FC` 쓰지 않는다
- 파일 하나에 컴포넌트 하나 (내부 전용 소형 하위 컴포넌트는 예외)
- props가 6개를 넘으면 설계를 다시 본다
- `ui` 레이어에서 fetch·스키마 파싱 금지 (INV-1). 데이터는 `state` 훅으로 받는다

## 상태 (GR-5)

| 종류 | 두는 곳 |
|---|---|
| 화면 한 곳의 UI 상태 | `useState` — 컴포넌트 로컬 |
| 서버/영속 데이터 (GitHub API) | TanStack Query — `state` 레이어의 훅 |
| 관리자 세션 (토큰) | `src/shared/providers/` 세션 프로바이더. 기본 sessionStorage ([SECURITY.md §3](SECURITY.md)) |
| 화면 간 공유 클라이언트 상태 | 최소한의 스토어. 도입 전 대안을 먼저 검토 |
| URL로 표현 가능한 상태 (필터, 탭, 상세 id) | **URL에 둔다.** 공유·새로고침이 되어야 한다 |

## 데이터 경계 (INV-3)

`data` 레이어 함수는 **파싱된 도메인 타입만 반환**한다.
빌드타임에 가져온 `content/` JSON 도, GitHub API 응답도 예외가 아니다.
`unknown`을 받아 스키마로 통과시킨 값만 밖으로 내보낸다. `as`로 형태를 주장하지 않는다.
파싱 실패는 삼키지 않고 도메인 에러로 변환한다 (GR-4).

## 라우팅

- 라우트 정의는 `app/`에 모은다. 도메인이 자기 라우트를 몰라도 되게 한다
- GitHub Pages 정적 호스팅 제약을 고려한다 (딥링크 새로고침 404 → EP-0001)
- 관리자 모드 라우트는 **코드 스플리팅**으로 분리한다. 이는 성능 목적이지 보안이 아니다 (INV-11)

## 성능

포트폴리오는 첫인상이 전부다. 다음만 지키면 충분하다:
- 이미지: 적절한 포맷·크기, `loading="lazy"`, 명시적 width/height (레이아웃 시프트 방지)
- 라우트 단위 코드 스플리팅
- 폰트: 서브셋 + `font-display: swap`
- 조기 최적화 금지. 측정 없이 `memo`를 뿌리지 않는다

## 폼 (주로 관리자 모드)

- 스키마가 진실이다. 같은 Zod 스키마로 검증하고 타입을 뽑는다
- 저장 실패 시 입력값을 잃지 않는다
- 파괴적 동작(삭제)은 확인을 받는다
- 커밋 실패는 원인별로 구분해 알린다 (네트워크 / 권한 없음 / 충돌). "저장 실패" 한 줄로 뭉개지 않는다 (GR-4)
