# EP-0007: 글쓰기 편집기 — 서식 도구·미리보기·이미지 첨부

- **상태**: DONE
- **시작**: 2026-09-09
- **관련**: [admin-editor 스펙](../../product-specs/admin-editor.md) · [ADR-0003](../../design-docs/adr/0003-content-store.md) · [SECURITY.md](../../SECURITY.md)

## 목표

지금 본문 입력은 **고정폭 12px 맨 텍스트 상자** 하나다. 사이트 글꼴과 달라서
쓰는 화면과 나오는 화면이 따로 놀고, 마크다운 문법을 외워야 한다. 사진도 못 넣는다.

관찰 가능한 결과:
1. 편집기 글꼴이 사이트 본문과 같다
2. 서식 도구로 굵게·제목·목록·인용·링크·코드를 문법 없이 넣는다
3. **미리보기**가 공개 사이트와 똑같이 렌더된다
4. 이미지를 끌어다 놓거나 골라서 넣으면 본문에 삽입되고, 공개 사이트에서 보인다

## 왜 위지윅이 아닌가

노션식 위지윅은 **HTML 을 저장**한다. 그러면 렌더할 때 원시 HTML 을 넣어야 하는데,
그 순간 XSS 경로가 열린다 — [SECURITY.md](../../SECURITY.md) 가 `rehype-raw` 류를
금지한 이유가 그것이다. 저장 형식을 HTML 로 바꾸면 스키마도 함께 갈아엎어야 한다.

그래서 **마크다운은 유지하고 도구를 얹는다.** 사용자는 문법을 몰라도 되고,
저장 형식은 그대로다. "쓰는 화면과 보는 화면이 다르다" 는 문제는 **미리보기**로 푼다 —
공개 사이트가 쓰는 `Markdown` 컴포넌트를 그대로 불러 쓰므로 결과가 어긋날 수 없다.

## 영상은 파일로 받지 않는다

콘텐츠는 git 저장소에 들어가고 GitHub Pages 가 서빙한다. 영상 파일을 커밋하면:

- 저장소가 영구히 무거워진다 (git 은 이력을 지우지 않는다)
- GitHub 은 파일 하나에 100MB, Pages 사이트에 1GB 를 넘기지 말라고 한다
- 매 배포마다 그 용량을 다시 빌드·업로드한다

그래서 **영상은 유튜브 등에 올리고 링크로 넣는다.** 이미지는 파일로 받는다.

## 구현 중 걸린 것

**툴바 버튼을 누르면 선택 영역이 풀렸다.** 버튼이 포커스를 가져가면서 textarea 의
선택이 사라져, "굵게" 가 선택한 글자가 아니라 커서 자리에 기호만 넣었다.
`mousedown` 기본 동작을 막아 포커스를 textarea 에 남겼다.

**서식을 넣은 뒤 커서가 글 끝으로 튀었다.** 선택 복원을 `requestAnimationFrame` 으로
했는데, React 가 새 값을 커밋하기 전에 돌아 헛돌았다. 복원 대상을 ref 에 담아두고
`value` 가 바뀐 뒤 `useEffect` 에서 복원하도록 고쳤다.

둘 다 브라우저에서 실제로 눌러 보고 나서야 드러났다 — 단위 테스트로는 안 잡힌다.
