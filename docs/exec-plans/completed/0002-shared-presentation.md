# EP-0002: 표시 레이어 공유 + admin 을 같은 화면으로

- **상태**: DONE
- **시작**: 2026-09-06
- **관련**: [ADR-0005](../../design-docs/adr/0005-shared-presentation.md), [admin-editor.md](../../product-specs/admin-editor.md)

## 목표

**admin 이 viewer 와 똑같은 화면으로 보이고, 거기에 항목 추가·수정 버튼만 얹혀 있다.**
표시 코드는 한 벌만 존재한다.

## 완료 조건 (Acceptance)

- [x] `shared/portfolio` 에 표시 레이어(service·ui·app 셸·토큰)가 모여 있다
- [x] viewer 와 admin 이 **같은 컴포넌트**로 렌더된다 (복제 0)
- [x] admin 에서 섹션마다 "추가" 버튼이 보이고, 항목을 눌러 수정할 수 있다
- [x] viewer 에는 편집 UI 가 전혀 나타나지 않는다
- [x] **공개 번들에 편집 코드가 섞이지 않는다** (INV-8, 빌드 후 실측)
- [x] admin 에서 저장하면 화면이 바로 갱신된다
- [x] `lint:arch` 가 `shared/<패키지>/<레이어>/` 에도 레이어 규칙을 적용한다
- [x] `npm run verify` 통과, 라이트/다크·모바일 확인

## 범위 밖

- 필드별 폼 (지금은 JSON 편집 유지 — 별도 항목)
- 삭제 UI
- 이미지 업로드

## 단계

- [x] 1. `shared/portfolio` 패키지 생성 + 워크스페이스 등록
- [x] 2. 순수 규칙(service) 이동 — select · search + 테스트
- [x] 3. 표시 컴포넌트(ui) 이동 — 히어로·목록·카드·마크다운·공통
- [x] 4. 셸(app) 이동 — 배너·검색·테마·라우트·레이아웃·토큰
- [x] 5. 페이지를 props 기반으로 전환 (훅 직접 호출 제거)
- [x] 6. 편집 슬롯 도입 — viewer 는 미주입, admin 만 주입
- [x] 7. viewer 를 얇게 (데이터 출처 + 조립만)
- [x] 8. admin 을 같은 화면으로 재작성 + 추가/수정 버튼
- [x] 9. `lint:arch` 레이어 검사 범위 확장
- [x] 10. verify + 양쪽 앱 `/ui-verify` + 번들 검사
- [x] 11. 문서 갱신 후 `completed/` 로 이동

## 결정 로그

| 날짜 | 결정 | 이유 |
|---|---|---|
| 2026-09-06 | 표시 레이어를 `shared/portfolio` 로 승격 | admin 이 viewer 와 같은 화면이어야 한다는 요구. 복제하면 한쪽만 고치는 사고가 확정된다 (CB-10) |
| 2026-09-06 | 페이지는 콘텐츠를 props 로 받는다 | 출처(빌드타임 glob vs API)가 달라도 같은 컴포넌트를 쓸 수 있다 |
| 2026-09-06 | 편집 기능은 선택적 슬롯 주입 | viewer 가 아무것도 넘기지 않으면 공개 번들에 편집 코드가 들어가지 않는다 (INV-8) |

| 2026-09-06 | 공유 패키지의 셸 폴더를 app/ 이 아니라 shell/ 로 | app/ 은 앱의 조립 루트를 뜻한다. 같은 이름을 쓰니 '누구도 app/ 을 import 하지 않는다' 규칙과 의미가 충돌했다. 규칙을 약화시키는 대신 이름을 바꿨다 |
| 2026-09-06 | verify 에 build 단계를 추가 | 타입체크·린트가 통과해도 번들은 깨질 수 있다. 실제로 두 번 겪었다. verify 가 통과라고 하면 배포 가능한 상태여야 한다 |
