# EP-0004: 항목별 복구·게시

- **상태**: DONE
- **시작**: 2026-09-08
- **관련**: [ADR-0003](../../design-docs/adr/0003-content-store.md) · [admin-editor 스펙](../../product-specs/admin-editor.md) · [EP-0003](../completed/0003-delete-content.md)

## 목표

게시가 **전부 아니면 전무**다. 셋을 고쳤는데 하나만 내보내고 싶으면 방법이 없고,
잘못 고친 것을 되돌리려면 터미널에서 `git checkout` 을 쳐야 한다.

게시 모달을 **목록에서 작업대로** 바꾼다. 각 줄에서 그 항목만 복구하거나 게시한다.

관찰 가능한 결과:
1. 모달의 각 줄에 `복구` · `게시` 버튼이 있다
2. 한 항목만 게시하면 **나머지는 미게시로 남는다**
3. 복구하면 그 항목만 마지막 게시 상태로 돌아간다 (새 항목이면 사라진다)
4. 전체 게시는 그대로 있다

## 완료 조건 (Acceptance)

- [x] 항목별 게시가 그 파일만 커밋한다 — 다른 미게시 변경은 남는다
- [x] 항목별 복구가 그 파일만 되돌린다
- [x] **복구는 확인을 거친다** — 미게시 편집은 되살릴 수 없다
- [x] 서버가 **pendingChanges 에 없는 경로를 거부**한다 (경로를 신뢰하지 않는다)
- [x] 소스 코드가 커밋되지 않는다 (기존 보장 유지)
- [x] `npm run verify` 통과
- [x] 관련 문서 갱신 (INV-10)

## 범위 밖

- **여러 항목 선택 후 한꺼번에 게시** (체크박스) — 전체 게시와 개별 게시로 충분하다
- **게시 취소(이미 푸시한 것 되돌리기)** — `git revert` 영역이다. 화면에 넣지 않는다
- 되돌리기 이력·휴지통 — git 이 이력이다
- viewer 변경 없음

## 위험 — 경로를 신뢰하면 안 된다

복구·게시 대상 경로가 **클라이언트에서 온다.** 그대로 git 에 넘기면
`content/` 밖의 파일을 되돌리거나 커밋할 수 있다.

방어: 요청 경로를 `pendingChanges()` 결과와 대조해 **그 목록에 있는 것만** 처리한다.
허용 목록을 git 자신에게서 얻으므로 문자열 검사보다 강하다.
기존 `shell: false` 원칙도 유지한다.
