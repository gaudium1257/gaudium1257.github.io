# EP-0010: 검색에 스펙 포함 + 단축키

- **상태**: DONE
- **시작**: 2026-09-09
- **관련**: [navigation-shell 스펙](../../product-specs/navigation-shell.md) · [ADR-0004](../../design-docs/adr/0004-navigation-shell.md)

## 목표

검색이 **반쪽이다.** `buildIndex` 가 논문·프로젝트·글만 받는다:

```ts
buildIndex({ papers, projects, posts })
```

그래서 검색창에 `고려대` 를 쳐도 아무것도 안 나온다. About 페이지에 버젓이 있는데도.
`React` 도 기술 스펙이 아니라 프로젝트 태그에 걸린 것만 나온다.

관찰 가능한 결과:
1. 학력·경력·기술·수상·자격증이 검색된다
2. 스펙 결과를 고르면 About 의 **그 항목 위치**로 간다
3. `/` 또는 `Ctrl/⌘+K` 로 검색이 열린다

- [x] 스펙 결과를 고르면 About 의 해당 항목으로 스크롤된다 (섹션 맨 위가 아니라)

- [x] 관련 문서 갱신 (INV-10)

## 범위 밖

- 검색 결과 순위·가중치 — 지금은 단순 포함 검색이다. 항목이 늘면 그때 본다
- 프로필(이름·한 줄 소개) 색인 — 이미 모든 화면에 보인다
- 검색 전용 페이지 — 드롭다운으로 충분하다
- 자동완성·오타 교정

## 설계 판단 — 스펙은 상세 페이지가 없다

논문·프로젝트·글은 `/papers/<id>` 같은 제 주소가 있는데 **스펙은 없다.** About 안의 한 줄이다.
그래서 결과를 눌렀을 때 갈 곳을 정해야 한다:

| 안 | 결과 |
|---|---|
| `/about` | 맨 위로 간다. 어느 항목이었는지 사용자가 다시 찾아야 한다 |
| `/about#<분류>` | 섹션까지는 간다. 항목이 많으면 여전히 찾아야 한다 |
| **`/about#spec-<id>`** | 그 줄로 간다. `SpecSection` 에 항목별 id 만 붙이면 된다 |

셋째를 택한다. 검색은 **찾아주는 것**이지 근처까지 데려다주는 게 아니다.

## 단계

- [x] 1. `SearchKind` 에 `spec` 추가, `buildIndex` 가 스펙을 받는다 + 테스트
- [x] 2. `SpecSection` 항목에 `id` + `scroll-margin` (고정 헤더에 가리지 않게)
- [x] 3. 두 앱의 `buildIndex` 호출에 스펙 전달
- [x] 4. 단축키 훅 — 입력 중에는 동작하지 않는다 + 테스트
- [x] 5. 검색 입력에 단축키 힌트 표시
- [x] 6. 브라우저 실측 + 문서 갱신 + `npm run verify`

### 검증 과정에서 잡은 것

처음 구현은 **URL 만 바뀌고 스크롤이 안 됐다.** URL 만 보고 넘어갔으면 놓쳤을 문제다.
원인을 좇는 과정에서 세 가지를 더 고쳤다 — `smooth` 무동작, 숨은 탭에서 rAF 미호출,
재시도 루프 폭주. 모두 결정 로그에 남겼다.
