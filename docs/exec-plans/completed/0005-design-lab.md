# EP-0005: 디자인 시안 비교소 (design-lab)

- **상태**: DONE
- **시작**: 2026-09-08
- **관련**: [ADR-0005](../../design-docs/adr/0005-shared-presentation.md) · [docs/DESIGN.md](../../DESIGN.md)

## 목표

디자인을 **말로 합의하지 못한다.** 지난번에 "일반적이다" → 시안 하나 → "폰트·색은 그대로" →
전체 롤백으로 한 바퀴를 돌았다. 한 번에 하나씩 보여주니 비교가 안 됐다.

**여러 시안을 나란히 놓고 고르는 로컬 사이트**를 만든다.

관찰 가능한 결과:
1. `npm run dev:lab` 으로 뜨는 세 번째 사이트가 있다
2. 시안을 목록에서 골라 즉시 전환할 수 있다
3. 각 시안이 **실제 콘텐츠**로 렌더된다 — 더미 텍스트로는 판단이 안 된다
4. 공개 배포에 절대 섞이지 않는다

## 완료 조건 (Acceptance)

- [x] 시안 5개 이상, 목록에서 전환 가능
- [x] 실제 `content/` 를 읽어 렌더한다 (스키마 파싱, INV-3)
- [x] **배포 산출물에 design-lab 이 없다** — 워크플로가 viewer 만 빌드한다
- [x] 라이트/다크 양쪽에서 깨지지 않는다
- [x] `npm run verify` 통과
- [x] 관련 문서 갱신 (INV-10)

## 범위 밖

- **시안을 실제 사이트에 적용하기** — 고르는 게 이번 일이다. 적용은 고른 뒤 별도 작업
- `shared/portfolio` 수정 — 시안은 자기 코드로 그린다. 공용 표시 레이어는 손대지 않는다
- 시안의 완성도 — 홈 화면 수준으로 충분하다. 전 페이지를 다섯 벌 만들지 않는다
- 반응형·접근성 정밀 검증 — 고른 시안에만 한다
- viewer/admin 동작 변경 없음

## 규칙 변경

`design-lab/src/concepts/` 를 **하드코딩 색 금지에서 제외**했다 (훅·린터 양쪽).

근거: 규칙의 이유는 "테마 토글이 토큰만 바꾸므로 하드코딩 색이 다크에서 깨진다" 인데,
시안은 `dark` 를 받아 두 팔레트를 직접 계산하므로 그 이유가 닿지 않는다.
오히려 공용 토큰을 강제하면 시안이 전부 같은 색이 되어 비교라는 목적이 사라진다.
우회가 아니라 **규칙을 근거가 닿는 범위로 좁힌 것**이다.

`design-lab/src` 를 린터 검사 대상에 추가했으므로 `any` 금지·파일 길이는 그대로 적용된다.

## 잔여 작업

- 시안을 고른 뒤 실제 적용 — 사용자가 고르면 별도 작업으로 진행한다
- 시안은 홈 화면 수준까지만 그렸다. 상세 페이지는 고른 뒤에 만든다
